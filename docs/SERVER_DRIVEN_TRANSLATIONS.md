# Server-Driven Translations via Firebase Remote Config

## Overview

Element X iOS currently uses static `.strings` / `.stringsdict` files generated by [Localazy](https://localazy.com). This guide explains how to **layer server-driven string overrides on top** using Firebase Remote Config, so you can change UI copy without shipping an app update.

---

## Architecture Approach

```
Firebase Remote Config
        │
        ▼
RemoteTranslationService   ←  fetches & caches overrides on app launch
        │
        ▼
L10n (custom wrapper)      ←  checks overrides first, falls back to bundle strings
        │
        ▼
SwiftUI Views
```

You do **not** replace `L10n` entirely. You wrap it so that overrides are checked first.


Download it from the [Firebase Console](https://console.firebase.google.com) and add it to the `ElementX/SupportingFiles/` folder. Make sure it is included in the app target.

## Step 2 – Create the Remote Translation Service

Create a new file:
`ElementX/Sources/Services/RemoteTranslations/RemoteTranslationService.swift`

```swift
import FirebaseRemoteConfig
import Foundation

/// Fetches and caches string overrides from Firebase Remote Config.
/// Keys must match exactly the L10n string key names (e.g. "screenCreateRoomNameLabel").
final class RemoteTranslationService {
    static let shared = RemoteTranslationService()

    private var overrides: [String: String] = [:]
    private let remoteConfig = RemoteConfig.remoteConfig()

    private init() {
        let settings = RemoteConfigSettings()
        // In DEBUG, fetch every 0 seconds so changes appear immediately.
        // In production keep the default 12-hour minimum fetch interval.
        #if DEBUG
        settings.minimumFetchInterval = 0
        #endif
        remoteConfig.configSettings = settings
    }

    /// Call this once from AppCoordinator / AppDelegate after Firebase.configure().
    func fetchAndActivate() async {
        do {
            let status = try await remoteConfig.fetchAndActivate()
            if status != .error {
                buildOverridesCache()
            }
        } catch {
            // Non-fatal – app falls back to bundled strings.
        }
    }

    /// Returns a server-provided override for `key`, or nil if none exists.
    func string(forKey key: String) -> String? {
        overrides[key]
    }

    // MARK: - Private

    private func buildOverridesCache() {
        var result: [String: String] = [:]
        for key in remoteConfig.allKeys(from: .remote) {
            let value = remoteConfig.configValue(forKey: key).stringValue
            if !value.isEmpty {
                result[key] = value
            }
        }
        overrides = result
    }
}
```

## Step 3 – Create the L10n Override Wrapper

Create:
`ElementX/Sources/Services/RemoteTranslations/L10nOverride.swift`

```swift
import Foundation

/// Drop-in helpers that check Firebase overrides before falling back to bundled strings.
///
/// Usage:  replace   L10n.someKey
///         with      L10nOverride.string("someKey") ?? L10n.someKey
///
/// Or use the convenience subscript:
///         L10nOverride["someKey"] ?? L10n.someKey
enum L10nOverride {
    static func string(_ key: String) -> String? {
        RemoteTranslationService.shared.string(forKey: key)
    }

    static subscript(_ key: String) -> String? {
        string(key)
    }
}
```

## Step 4 – Initialize Firebase on App Launch

In `ElementX/Sources/Application/AppCoordinator.swift` (or wherever the app starts):

```swift
import FirebaseCore
import FirebaseRemoteConfig

// Inside the app entry point, before anything else:
FirebaseApp.configure()

// Then kick off the translation fetch (non-blocking):
Task {
    await RemoteTranslationService.shared.fetchAndActivate()
}
```

---

## Step 5 – Use Overrides in Views

For any string you want to be remotely overridable, change:

```swift
// Before
Text(L10n.screenCreateRoomNameLabel)

// After
Text(L10nOverride["screenCreateRoomNameLabel"] ?? L10n.screenCreateRoomNameLabel)
```

You can wrap this in a small helper to keep views clean:

```swift
func t(_ key: String, fallback: String) -> String {
    L10nOverride[key] ?? fallback
}

// Usage
Text(t("screenCreateRoomNameLabel", fallback: L10n.screenCreateRoomNameLabel))
```

---

## Step 6 – Define Keys in Firebase Console

1. Open [Firebase Console](https://console.firebase.google.com) → your project → **Remote Config**.
2. Click **Add parameter**.
3. Set the **Parameter key** to the exact `L10n` key name (e.g. `screenCreateRoomNameLabel`).
4. Set the **Default value** to the override string.
5. Publish changes.

> **Tip:** Use **Conditions** in Firebase to serve different strings per locale (`device.language`), app version, or user segment.

---

## Step 7 – Plurals & Format Strings

For strings with `%@` / `%d` format arguments:

```swift
// Firebase value:  "Welcome, %@! You have %d new messages."
// Key:             "welcomeMessage"

if let template = L10nOverride["welcomeMessage"] {
    let result = String(format: template, username, messageCount)
} else {
    let result = L10n.welcomeMessage(username, messageCount)
}
```

Store format strings in Firebase exactly as they appear in the `.strings` file, including `%@`, `%d`, `%1$@`, etc.

---

## Step 8 – Live Reload (Optional)

To react to Remote Config updates while the app is in the foreground:

```swift
remoteConfig.addOnConfigUpdateListener { [weak self] _, error in
    guard error == nil else { return }
    Task { @MainActor in
        try? await remoteConfig.activate()
        self?.buildOverridesCache()
        // Post a notification so views can refresh if needed
        NotificationCenter.default.post(name: .remoteTranslationsUpdated, object: nil)
    }
}
```

## Caching & Offline Behaviour

| Scenario | Behaviour |
|---|---|
| App launched, no network | Uses last activated Remote Config values (persisted to disk by SDK) |
| First ever launch, no network | Falls back to bundled `.strings` files |
| Firebase fetch fails | Silent — app uses bundled strings |
| Remote Config value is empty string | Treated as "no override", falls back to bundled |

---

## Security Considerations

- Remote Config values are **not encrypted** and are visible to anyone who decompiles the app. Do **not** store sensitive data there.
- Use Firebase App Check to prevent unauthorised clients from fetching your config.
- Translations are read-only from the client perspective — only your Firebase Console can publish changes.

---

## Key Naming Convention

Use the same key names as Localazy / generated `L10n` enum cases, converting camelCase to the raw string key:

| `L10n` call | Firebase key |
|---|---|
| `L10n.screenCreateRoomNameLabel` | `screenCreateRoomNameLabel` |
| `L10n.commonMemberCount(n)` | `commonMemberCount` (handle `%d` yourself) |
| `L10n.roomDetailsTopicTitle` | `roomDetailsTopicTitle` |
